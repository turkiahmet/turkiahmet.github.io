# لوحة التحكم العربية الخاصة — الإصدار التنفيذي ٢

خدمة خلفية مستقلة للموقع العام https://turkiahmet.github.io/، مع لوحة محمية قبل إرسال HTML الخاص. الهدف المنشأ في حساب Cloudflare: https://turkiahmet-admin.turkiahmet26.workers.dev . لم تنشر هذه الحزمة بواسطة وكيل التنفيذ؛ يتولى الوكيل الرئيسي النشر والتحقق من البيئة الحقيقية.

## الملفات الجاهزة

- `worker.js`: حزمة ESM واحدة مكتفية بالأصول النصية، تلصق في محرر Cloudflare Worker.
- `schema.sql`: تُطبق على قاعدة D1 جديدة ثم تربط باسم `DB`.
- `src/helpers.js` و`src/app.js`: المصدر القابل للصيانة.
- `public/`: واجهة دخول وواجهة إدارة منفصلتان؛ الملفات الخاصة لا تُرسل دون جلسة.
- `test.mjs`: اختبارات Node/SQLite حقيقية، لا تحتوي رموز حسابات فعلية.

إعادة البناء: `node build.mjs` ثم `node --test test.mjs` و`node --check worker.js`.

## ربط البيئة

1. D1 binding باسم `DB`، مع جميع جداول schema.sql.
2. `GOOGLE_CLIENT_ID`: معرّف عميل OAuth Web من Google Identity Services. الـAuthorized JavaScript origin هو **https://turkiahmet-admin.turkiahmet26.workers.dev** دون مسار. تدفق تسجيل الهوية الحالي لا يحتاج Client Secret ولا صلاحية Gmail أو Drive.
3. `SESSION_SECRET`: سر عشوائي لا يقل عن ٣٢ حرفًا، يضاف Secret في إعدادات Worker. لا يوضع في المصدر أو ملف GitHub أو التقارير.
4. `GITHUB_TOKEN`: Secret للنشر إلى مستودع **turkiahmet/turkiahmet.github.io** وحده؛ الحد اللازم Contents read/write وActions read. لا يُرسل للمتصفح.
5. `CONTACT_ENABLED=true` و`ANALYTICS_ENABLED=true` لتشغيلهما بعد اكتمال المصادقة وقاعدة البيانات.
6. اختياريًا `OWNER_GOOGLE_SUB` إذا أراد المالك تثبيت Google sub مسبقًا. وإلا يثبت أول sub بتوقيع Google صحيح وبريد المالك المتحقق **turkiahmet26@gmail.com**. لا يقبل sub آخر بعد ذلك ولو تغيّر بريد مستعمل آخر إلى العنوان نفسه.
7. إعدادات حصة اختيارية: `CONTACT_MAX_LENGTH` الافتراضي 3000 حرف Unicode، `CONTACT_HOURLY_LIMIT` الافتراضي 5 لكل مصدر اتصال/ساعة، `CONTACT_CAPACITY` الافتراضي 1000 رسالة محفوظة. هذه حدود تنفيذ افتراضية قابلة للتعديل وليست أرقامًا تاريخية اعتمدها المستخدم. **لا حذف تلقائي للرسائل**؛ الصندوق يرفض مؤقتًا إذا امتلأ.

لا يحتاج Worker الحالي ASSETS binding أو Turnstile. مقاومة الإرسال الآلي تعتمد على Origin وحجم النص وقائمة حقول محددة وhoneypot وحصة قصيرة لكل مصدر اتصال. إذا ازداد الإزعاج يمكن إضافة تحقق آلي لاحقًا.

## تشغيل المحتوى

- انشر أولًا مصدر الموقع المحدث في GitHub وفيه `content/site-data.json` و`tools/build_site.py` والنشر الذي يستدعي التوليد.
- افتح `/admin` وسجّل بحساب المالك. يظهر HTML الدخول وحده للزائر؛ لا HTML المحرر أو الرسائل أو الإحصاءات.
- اضغط **استيراد الموقع الحالي أول مرة**. يقرأ GitHub مصدر المحتوى العام ويخزن نسخته في D1، مع SHA لمنع الكتابة فوق تغيير خارجي.
- يمكن تحرير النبذة والعمل وحفظه خاصًا، أو إدراجه في النشر العام التالي. **الحالة العلمية** منفصلة عن **الظهور**: مقال قيد الإعداد يمكن عرضه كعمل جارٍ، والمسودة تبقى خاصة.
- معاينة البيانات العامة تستبعد المسودات والرسائل، وتتطلب وجود سجل الماجستير المعتمد لمنع مصدر عام فارغ.
- **اعتماد النشر** يكتب ملف `content/site-data.json` وحده عبر Contents API ثم يبدأ GitHub Actions. لا يدّعي النجاح النهائي بمجرد حفظ الالتزام؛ زر **تحقق من النشر** يفحص نتيجة التشغيل.
- إذا تغير SHA المصدر من خارج اللوحة، يرجع نشرها 409 ويطلب مراجعة ودمج التغييرات. لا يتجاوز هذا الحارس تلقائيًا. الدمج الخارجي يحتاج مسار صيانة مقصود قبل إعادة ربط أساس النشر، حتى لا يضيع تحرير متوازٍ.
- استعادة نسخة من سجل profile أو research تعيدها في D1 فقط، والعمل المستعاد يصبح مسودة خاصة. يلزم النشر صراحة لتغيير الموقع.

## الصيغة العامة المتفق عليها

```json
{"schemaVersion":1,"profile":{"ar":{"displayName":"...","role":"...","tagline":"...","bio":"...","interests":["..."]},"tr":{},"en":{}},"works":[{"id":"sharh-al-tawilat-2021","title":{"ar":"...","tr":"...","en":"..."},"summary":{"ar":"...","tr":"...","en":"..."},"keywords":{"ar":[],"tr":[],"en":[]},"type":"masters_thesis","status":"published","year":2021,"officialUrl":"https://...","imageUrl":"","videoUrl":""}]}
```

نوع العمل من `masters_thesis|doctoral_thesis|article|other`، وحالته العلمية من `published|in_progress`. في الإدارة يوجد حقل `visibility: draft|public` خاص لا ينشر إلى GitHub. المعرّف ثابت بأحرف صغيرة وأرقام وواصلات. تفاصيل الماجستير الأصلية والاستشهادات الثابتة يحتفظ بها مولد الموقع بمعرّفه.

## رفع ملفات المالك العامة

- قسم «الملفات العامة» في لوحة الإدارة يرفع الصور ونسخ السيرة PDF باستخدام `POST /api/admin/uploads` بصيغة multipart، خلف جلسة المالك وOrigin وCSRF نفسيهما.
- حقل واحد `file` وحقل `kind` من image أو cv؛ يرفض الملفات الزائدة والحقول الأخرى.
- الأنواع المقبولة: PNG وJPEG وWebP للصورة وapplication/pdf للسيرة. يفحص النوع المعلن والتوقيع الثنائي، وأبعاد PNG وRIFF الخاص بـWebP ونهاية PDF. لا HTML أو SVG؛ هذا فحص صيغة أولي، لا ادعاء فحص برمجيات خبيثة شامل.
- الحد الافتراضي ٥ MiB، يمكن ضبط `OWNER_UPLOAD_MAX_BYTES` بين ١٠٠ KiB و١٠ MiB.
- ينشئ ملفًا جديدًا في مسار ثابت `site/uploads/images/UUID.ext` أو `site/uploads/cv/UUID.pdf` داخل المستودع نفسه. لا ينقل اسم الملف الأصلي إلى الرابط العام.
- تظهر للمالك قبل الرفع رسالة تؤكد أن الملف ينشر في مستودع عام ويمكن بقاؤه في سجل Git؛ السيرة تُراجع من المالك قبل ذلك. لا يرفع وكيل التنفيذ أي ملف شخصي بمجرد وجوده في حسابه.
- يعيد الرابط العام ومعرّف الالتزام ورابط متابعة Actions. سجل الإيصالات في جدول revisions الموجود؛ **لا ترحيل قاعدة بيانات جديد**. يسهل نسخ الرابط لاستخدامه في بيانات العمل أو المصدر المناسب.
- يظل نموذج زوار الموقع بلا مرفقات؛ هذه القدرة حصرية للمالك. لا يتغير حارس مصدر المحتوى بعد رفع صورة؛ فهو يقارن SHA لملف content/site-data.json، لا رأس الفرع. يجب أن يحافظ مولد الموقع على site/uploads/.

## المراسلة والإحصاءات

الموقع العام يضبط `/site/services.json` إلى `{ "backendOrigin": "https://turkiahmet-admin.turkiahmet26.workers.dev" }` **بعد** نجاح الاختبار الحقيقي.

- `GET /api/config`: يعيد حالة التفعيل وحدود الرسالة ورابط الإدارة. لا أسرار فيه.
- `POST /api/contact`: حقوله message المطلوبة، وname/email/subject الاختيارية، وwebsite للـhoneypot. JSON فقط؛ المرفقات والحقول الزائدة مرفوضة. يقبل Origin موقع GitHub وحده. لا إرسال Gmail أو رسائل نيابة عن المالك.
- صندوق الإدارة يعرض النص بوصفه نصًا، مع مقروءة/أرشفة/حذف نهائي بتأكيد/تصدير CSV خاص. يحمي تصدير CSV من صيغ الجداول التي تبدأ = أو + أو - أو @.
- `POST /api/analytics`: `{path,referrer,visit}` فقط. لا معرّف زائر، ولا أسماء أو بريد، ولا IP كامل محفوظ. يخزن مجموع المشاهدات والزيارات حسب اليوم UTC والمسار والبلد التقريبي ومضيف الإحالة والجهاز. يتجاهل bots الواضحة، والحصة تقيد الإغراق. بيانات البلد تأتي من Cloudflare لا حقل يرسله الزائر.
- الزيارة session تقديرية حسب علامة زمنية لكل تبويب في الواجهة العامة؛ ليست عدد أشخاص فريدين. لا تدّعي الإحصاءات معرفة هوية الزوار. حجب JavaScript/الشبكة أو الإرسال الآلي قد يؤثر في دقة الأعداد.
- تقييد مصادر الطلب ليس إثباتًا أن كل إحصاء صدر من إنسان؛ CORS لا يحمي من عملاء HTTP خارج المتصفح. هذه قياسات استعمال عملية، لا نظام حضور أو تدقيق هوية.
- أسماء الزوار تظهر فقط إن تركوا اسمًا اختياريًا في رسالة. أدوات القياس لا تستخرج أسماءهم أو جامعاتهم.
- جدول rate_limits يحفظ بصمة قصيرة العمر مشتقة بسر من عنوان الاتصال مع الساعة، ويحذف المنتهي. عدم حفظ عنوان IP كامل في التطبيق لا يعني أن مزود الشبكة لا يعالج بيانات النقل.

## الحماية المنفذة

تحقق توقيع RS256 بمفاتيح Google الرسمية وaud/iss/exp/iat/nonce/email_verified/bريد المالك، وربط sub ثابت. nonce أحادي الاستعمال، جلسة موقعة مع سجل قابل للإلغاء في D1، وHttpOnly/Secure/SameSite cookies. كل كتابة خاصة تتطلب Origin الخادم وCSRF. لا تخزين لرمز Google أو PAT في قاعدة البيانات، ولا إرجاعه في الخطأ. المحتوى التحريري ورسائل الزوار تعرض بواسطة textContent. CSP تمنع الإطارات والموارد غير المعلنة. صفحات الإدارة no-store/noindex. لا public API يعرض المسودات أو الرسائل أو سجل الإدارة.

## نتيجة الاختبارات المحلية

١٠ اختبارات ناجحة: حماية HTML/assets والـAPI، التحقق التشفيري للهوية ورفض التزوير والحساب الآخر، CSRF وإلغاء الجلسة، الاستيراد وحماية المصدر الفارغ واستبعاد المسودة من النشر، المراسلة الاختيارية والحصص ورفض المرفقات وCSV، الإحصاءات المجمعة بلا معلومات شخصية، بيانات الأعمال والروابط، واستعادة النسخة الخاصة ورفض SHA متعارض، ورفع الصور/PDF المصرح به ورفض غير المالك وCSRF والنوع المزيف وتجاوز الحجم وبقاء مصدر المحتوى صالحًا بعد الرفع.

لا تعادل الاختبارات المحلية دخول حساب المالك أو نشرًا حقيقيًا؛ يلزم إثبات ذلك في حساب Cloudflare وGoogle وGitHub الحالي من الوكيل الرئيسي.
